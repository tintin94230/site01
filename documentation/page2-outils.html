Page 2 – Outils, workflow & déploiement

Cette page décrit le cycle complet de développement : modification du code, tests locaux, sauvegarde Git et déploiement en production.

1. Outils utilisés

  • Visual Studio Code – édition du code
  • Git – gestion des versions
  • GitHub – hébergement du dépôt
  • Vercel – hébergement du site et des API
  • Supabase – base de données PostgreSQL
  • OVH – nom de domaine

2. Environnements

Développement local

  • Serveur local (localhost)
  • Variables stockées dans .env.local
  • Fichier non versionné

Production

  • Code hébergé sur Vercel
  • Variables d’environnement configurées dans Vercel
  • Aucun fichier sensible exposé
  • Site accessible publiquement à l’adresse : https://site01-snowy.vercel.app/

3. Workflow de développement

1️⃣ Modifier le code

Le développement est effectué localement avec Visual Studio Code. Chaque fonctionnalité est testée avant sauvegarde.

2️⃣ Tester en local

Site HTML / JavaScript simple

npx serve .

Projet avec Node / API

npm install
npm run dev

Le site est accessible via http://localhost.

3️⃣ Arrêter un serveur local

Commande standard :

CTRL + C

Si le port reste bloqué (Windows) :

netstat -ano | findstr :3000
taskkill /PID XXXX /F

4. Sauvegarde du code avec Git

Initialisation (une seule fois)

git init

Workflow standard

git status
git add .
git commit -m "Message clair décrivant la modification"

Envoi vers GitHub

git push

5. Déploiement

Déploiement de test (preview)

vercel

Déploiement production

vercel --prod

Après déploiement, le site de production est disponible ici : https://site01-snowy.vercel.app/

6. Tests

  • Tests via navigateur
  • Tests via fetch()
  • Vérifications via l’interface Supabase

7. Résumé

  • Toujours tester avant de pousser
  • Commit fréquemment
  • Ne jamais versionner les secrets
  • Déployer uniquement du code validé

8. Variables d’environnement sur Vercel

Pour connecter votre site à Supabase, les variables d’environnement sont gérées via la page Vercel Environment Variables .

Principe

  • Chaque variable peut être assignée à Development, Preview, Production ou All Environments.
  • Pour avoir des valeurs différentes en DEV et PROD, ne jamais utiliser All Environments mais créer une variable distincte pour chaque environnement.

Exemple de configuration pour Supabase

VariableDEVPROD
SUPABASE_URLhttps://xxxx-dev.supabase.cohttps://xxxx-prod.supabase.co
SUPABASE_KEYkey_devkey_prod

Test local DEV

vercel env pull
# crée .env.local avec valeurs DEV

Redéploiement PROD

Après modification des variables PROD, il faut redéployer le projet : 

vercel --prod

Bonnes pratiques

  • Séparer DEV et PROD
  • Ne jamais exposer de clés sensibles côté front
  • Redéployer après modification PROD
  • Tester localement avec vercel dev et vercel env pull
  • Vérifier avec un endpoint test que les variables sont bien lues
