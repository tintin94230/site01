1️⃣ Backend – API Node.js / Vercel

Chaque fichier dans /api devient une fonction serverless accessible via /api/nom-du-fichier.

Exemple : API blog / mots

import { createClient } from '@supabase/supabase-js'

const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_KEY)

export default async function handler(req, res) {
  if(req.method === 'GET'){ ... }
  if(req.method === 'POST'){ ... }
  res.status(405).json({ error: 'Méthode non autorisée' })
}

2️⃣ Base de données – Supabase

Tables principales :

  • mots : id, mot, created_at
  • lieux : id, nom, latitude, longitude
  • itinéraires : id, lieu_depart_id, lieu_arrivee_id, type, description, lien

Bonnes pratiques :

  • Séparer DEV et PROD
  • Clés sensibles uniquement côté backend
  • Ne jamais exposer service_role côté front

3️⃣ Tests et appels API

Exemples :

  • OpenWeatherMap – météo actuelle
  • SNCF / Navitia – horaires
  • CRUD Supabase pour blog et lieux

4️⃣ Déploiement / Environnements

  • Vercel dev → local
  • Vercel → Preview (pré-prod)
  • Vercel --prod → production

Important : les variables d’environnement sont **injectées au moment du déploiement**.

5️⃣ Gestion de version – Git / GitHub

Commandes essentielles :

  • git add . / git commit -m "message" / git push
  • git branch -M main / git remote -v

6️⃣ Retours d’expérience et bonnes pratiques

  • DEV ≠ PROD → jamais mélanger les bases
  • Tester les API localement avant déploiement
  • Utiliser console navigateur pour debug
  • Un commit = une intention claire

7️⃣ Conclusion

Cette page documente les outils, le backend, les API et la méthodologie. Elle complète la Page 1 qui se concentre sur le site en lui-même.
