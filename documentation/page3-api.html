Page 3 – API internes & Base de données (v3)

Cette page documente les API backend internes et la structure complète de la base Supabase. Elle inclut les commandes pour explorer et modifier la base, et pour migrer DEV → PROD. De nouvelles tables et APIs sont désormais disponibles pour gérer les pays et leurs informations détaillées.

1️⃣ Principe général

Toutes les pages HTML passent par des API serverless hébergées sur Vercel. Aucune page n’accède directement à la base de données. 

Navigateur (HTML / JS)
        |
        v
API serverless (/api/*)
        |
        v
Supabase (PostgreSQL)

Avantages :

  • Clés Supabase protégées côté serveur
  • Centralisation de la logique métier
  • Séparation claire Frontend / Backend
  • Architecture prête pour évolutions futures

2️⃣ API /api/supabase001

Utilisée par blog.html pour stocker un mot saisi par l’utilisateur.

Objectif

API simple et pédagogique d’interaction HTML → Supabase.

Fonctions

  • Recevoir un mot depuis le navigateur
  • Calculer sa longueur
  • Insérer le mot dans la table mots

Endpoint

GET /api/supabase001?mot=bonjour

Flux

blog.html
   |
   | fetch("/api/supabase001?mot=bonjour")
   v
API supabase001
   |
   | INSERT INTO mots
   v
Supabase

Table mots

ColonneDescription
idIdentifiant unique (UUID / serial)
motMot saisi
created_atDate de création automatique

  • Logique métier côté serveur

Données manipulées

  • Lieux géographiques
  • Itinéraires entre lieux

Flux typique

admin-lieux.html
      |
      | fetch("/api/supabase002", data)
      v
API supabase002
      |

      v
Supabase

Sécurité

6️⃣ Commandes utiles Supabase

6.1 Explorer la base

supabase db remote commit
supabase db remote list
supabase db remote status

6.2 Ajouter une colonne

ALTER TABLE lieux ADD COLUMN description TEXT;
ALTER TABLE infos_pays ADD COLUMN source TEXT;

6.3 Copier la structure DEV → PROD

# Export DEV schema
supabase db dump --schema-only --file=dev_schema.sql

# Import PROD schema
supabase db restore --file=dev_schema.sql --project-ref=PROD_PROJECT_REF

6.4 Tester les requêtes SQL

# Exemple INSERT
INSERT INTO pays (nom, code_iso) VALUES ('France', 'FR');
INSERT INTO infos_pays (pays_id, categorie, texte, date_update) 
VALUES (1, 'transport', 'TGV et TER disponibles', NOW());

# Exemple SELECT
SELECT * FROM pays;
SELECT * FROM infos_pays WHERE pays_id=1;

# Exemple UPDATE
UPDATE infos_pays SET texte='Nouvelle info' WHERE id=1;

# Exemple DELETE
DELETE FROM infos_pays WHERE id=1;
