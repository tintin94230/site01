Page 4 – Astuces, Raccourcis & Bonnes pratiques

Cette page rassemble toutes les astuces et raccourcis pour manipuler les APIs et la base Supabase rapidement et en toute sécurité.

1️⃣ Astuces générales

  • Utiliser fetch("/api/...") pour tester rapidement vos APIs depuis le navigateur ou un script JS.
  • Mettre à jour DEV avant PROD pour éviter les conflits de schéma.
  • Conserver toutes les commandes SQL fréquentes dans un fichier sql-requetes.txt.
  • Pour les nouvelles tables pays et infos_pays, toujours vérifier que pays_id existe avant insertion.
💡 Astuce : Pour éviter les erreurs de clé étrangère, utiliser SELECT id FROM pays WHERE nom='France' avant d'insérer dans infos_pays.

2️⃣ Raccourcis DEV / PROD

ActionCommande / Astuce
Voir la structure DEVsupabase db remote status
Exporter schema DEVsupabase db dump --schema-only --file=dev_schema.sql

3️⃣ Astuces API spécifiques

  • supabase001 : parfait pour tester des inputs texte simples et montrer la logique JS → API → Supabase.
  • supabase002 : toujours vérifier les id des lieux avant INSERT ou UPDATE.
  • supabasePays : privilégier le CRUD via admin-pays.html pour éviter des doublons.
  • supabaseInfoPays : stocker les catégories cohérentes : transport, logement, réduction, loisir.
💡 Astuce : utiliser console.table()

4️⃣ Bonnes pratiques tables

  • Ne jamais modifier directement PROD, passer par DEV → migration.
  • Tenir à jour les date_update dans infos_pays à chaque modification.
  • Ajouter des contraintes SQL pour éviter les doublons, ex : UNIQUE(nom, code_iso) pour pays.
  • Pour les tests rapides, utiliser SELECT * FROM infos_pays WHERE pays_id=1 pour récupérer toutes les infos France.

5️⃣ Trucs & astuces rapides

  • 💾 Sauvegarde rapide : exporter uniquement le schema ou une table spécifique.
  • 🧹 Nettoyage : DELETE FROM mots WHERE created_at < NOW() - INTERVAL '30 days'
  • 📊 Debug front : console.log(await fetch('/api/supabasePays').then(r=>r.json()))
  • ⚡ Autocomplétion VSCode : installer plugin Supabase pour voir tables & colonnes directement.

6️⃣ Notes finales

- Toujours vérifier DEV avant PROD.
- Utiliser fetch côté navigateur pour tests rapides.
- Respecter les relations clés étrangères (pays → infos_pays, lieux → itineraires).
- Documenter chaque modification pour garder une trace dans CHANGELOG.md.
